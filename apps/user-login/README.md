# apps/user-login — 3-service login app

Log in, then see the user list from Postgres. Three microservices, deployed by Flux +
Kustomize into **`userlogin-dev-ns`** and **`userlogin-qa-ns`** (independent of the
`nginx-demo` app).

```
browser ──▶ user-login-ui  (React build, served by nginx)
                 │  nginx proxies /api/* ──▶ user-login-api  (Node/Express)
                 │                                │  pg
                 │                                ▼
                 │                        userlogin-db  (CloudNativePG Postgres)
                 │                          ▲        ▲
                 │             migrate Job ─┘        └─ reset CronJob (suspended)
                 ▼
        LoadBalancer + Azure DNS label
        userdir-<env>.eastus2.cloudapp.azure.com
```

| Service | Image | Tech | Talks to |
|---|---|---|---|
| `user-login-ui` | `user-login-ui:v1` | React (Vite) + nginx | proxies `/api` → `user-login-api:8080` |
| `user-login-api` | `user-login-api:v1` | Node 20 + Express + `pg` + `bcryptjs` + `jsonwebtoken` | `userlogin-db-rw:5432` |
| `userlogin-db` | CNPG default | Postgres via CloudNativePG `Cluster` CR | — |

## API

| Route | Auth | Returns |
|---|---|---|
| `POST /api/login` `{username,password}` | — | `{ token }` — JWT, 1 h, signed with `JWT_SECRET` |
| `GET /api/users` | `Authorization: Bearer <token>` | `[{id,username,full_name,email,created_at}]` |
| `GET /api/healthz` | — | `{ok:true,env}` |
| `GET /metrics` | — | Prometheus metrics (scraped by a `ServiceMonitor`) |

**Config (env):** `DATABASE_URL` = `uri` key of the CNPG-generated Secret
`userlogin-db-app`; `JWT_SECRET` = `secret` key of `userlogin-jwt` (from OpenBao via
ESO); `APP_ENV` = `dev` / `qa` (overlay patch).

## Database — CloudNativePG

`k8s/base/db-cluster.yaml` is a `postgresql.cnpg.io/v1` `Cluster`: 1 instance, 1 Gi PVC,
`initdb` creates database `userlogin` owned by role `appuser`. The operator
(`infrastructure/cnpg/`) then provides:

- Secret **`userlogin-db-app`** — `username / password / dbname / host / port / uri / …`
  (app credentials are **generated by CNPG**, never in git)
- Services **`userlogin-db-rw`** (primary), `-ro`, `-r`

## Migrations & fixtures

- **Schema** — plain numbered SQL in `api/migrations/*.sql`, applied by
  `api/src/migrate.js` (a ~40-line forward-only runner; tracks applied files in
  `schema_migrations`, one txn each). Add a migration = drop a new
  `NNN_name.sql` and rebuild the API image.
- **Fixtures** — `api/src/seed.js` inserts 5 demo users
  (`admin`, `bwayne`, `ckent`, `dprince`, `bbanner`), all password **`password123`**,
  `ON CONFLICT (username) DO NOTHING` → safe to re-run.
- **On every deploy** — `k8s/base/db-migrate-job.yaml` (`Job userlogin-db-migrate`) runs
  `node src/migrate.js && node src/seed.js`. It carries
  `kustomize.toolkit.fluxcd.io/force: enabled`, so Flux **recreates** it whenever its
  spec changes (new image / migration); it retries (`backoffLimit: 20`) until the DB
  answers; `ttlSecondsAfterFinished: 600` cleans it up.

### Reset a database (one namespace)

`k8s/base/db-reset-cronjob.yaml` ships a **suspended** `CronJob userlogin-db-reset`
(never-fires schedule). Trigger an on-demand run:

```bash
NS=userlogin-dev-ns    # or userlogin-qa-ns
kubectl -n $NS create job db-reset-$(date +%s) --from=cronjob/userlogin-db-reset
kubectl -n $NS get jobs -l job-name --sort-by=.metadata.creationTimestamp
kubectl -n $NS logs -f job/db-reset-<name>
```

It runs `node src/migrate.js --reset && node src/seed.js` →
`DROP SCHEMA public CASCADE; CREATE SCHEMA public;` then re-migrate + re-seed. Only that
namespace's DB is touched.

## Build the images

```bash
az acr build --registry sanaksregistry --image user-login-api:v1 ./apps/user-login/api
az acr build --registry sanaksregistry --image user-login-ui:v1  ./apps/user-login/ui
```

Bump the tag in **both** overlays' `kustomization.yaml` (`images[].newTag`) to roll a
new version; the migrate Job re-runs automatically.

## Deploy (Flux)

Reconciled by `clusters/dev/user-login-dev.yaml` / `user-login-qa.yaml`
(`dependsOn: [cnpg-operator, secrets]`). Add to the `az k8s-configuration flux create`:

```bash
  --kustomization name=cnpg-operator  path=./infrastructure/cnpg               prune=true \
  --kustomization name=user-login-dev path=./apps/user-login/k8s/overlays/dev  prune=true dependsOn=["cnpg-operator","secrets"] \
  --kustomization name=user-login-qa  path=./apps/user-login/k8s/overlays/qa   prune=true dependsOn=["cnpg-operator","secrets"]
```

Also: seed the JWT secret in OpenBao and let the `eso-monitoring` policy read
`kv/data/userlogin/*` (see repo root README §3.7 / `infrastructure/secrets/README.md`):

```bash
bao policy write eso-monitoring - <<'EOF'
path "kv/data/monitoring/*" { capabilities = ["read"] }
path "kv/data/userlogin/*"  { capabilities = ["read"] }
EOF
bao kv put kv/userlogin/jwt secret="$(openssl rand -hex 32)"
```

And create the `flux-applier` SA + binding in `userlogin-dev-ns`, `userlogin-qa-ns`,
`cnpg-system` (root README §3.6).

## Verify

```bash
kubectl get pods -n userlogin-dev-ns
kubectl get cluster,externalsecret,job,cronjob -n userlogin-dev-ns
kubectl -n userlogin-dev-ns exec userlogin-db-1 -- psql -U appuser -d userlogin -c 'SELECT id,username FROM users ORDER BY id;'

# UI URL:
kubectl get svc user-login-ui -n userlogin-dev-ns -o jsonpath='{.status.loadBalancer.ingress[0].ip}'
#   http://userdir-dev.eastus2.cloudapp.azure.com  → log in as admin / password123
```

## Local dev

```bash
# api  (needs a local Postgres; DATABASE_URL=postgres://user:pw@localhost:5432/userlogin)
cd apps/user-login/api && npm install && npm run migrate && npm run seed && npm start
# ui   (proxies /api to localhost:8080)
cd apps/user-login/ui && npm install && npm run dev
```
